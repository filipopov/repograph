**Short answer:** no consumer reads `currency` today, but every service that deserializes `AccountDto` gets a different JSON shape. Five production files in four repos are affected. Two public gateway endpoints pass the new shape straight to clients outside this workspace. No Kafka topic carries `AccountDto`.

## Affected production files

**bank-contracts**
- `src/main/java/dev/demobank/contracts/AccountDto.java:5`: change `String currency` to `Currency currency`. Add the `Currency` enum, with `@JsonFormat(shape = JsonFormat.Shape.OBJECT)` so it serialises as an object. If a client sends the old string, decoding fails unless you add a `@JsonCreator` that also accepts a plain string. Every other repo depends on this module, so it is the source of the change.

**accounts-service** (the producer)
- `AccountController.java:43-44` (`toDto`): `new AccountDto(..., account.currency(), ...)` stops compiling. Convert the value, for example `Currency.valueOf(account.currency())`, or change the domain model as well.
- `Account.java:5` (optional): the internal `Account` record also stores `String currency`. You can leave it, but if you change it, two more places follow:
  - `AccountService.java:51-53` (`checkCurrency`) compares `account.currency()` with `MoneyMovementRequest.currency()`, which is still a String.
  - `CurrencyMismatchException.java:9` takes the currency as Strings.
- The four endpoints whose responses carry the new shape: `GET /accounts`, `GET /accounts/{id}`, `POST /accounts/{id}/debit`, `POST /accounts/{id}/credit` (`AccountController.java:23-39`).

**gateway-service** (it decodes the response and passes it on unchanged)
- `client/AccountsClient.java:13,16`: `list()` and `get()` decode `GET /accounts` and `GET /accounts/{id}` into `AccountDto`. No code change, but the service must be rebuilt against the new contracts. Until then, decoding fails when accounts-service sends an object where a String is expected.
- `GatewayController.java:38-45`: re-exposes the DTO as-is on `GET /api/v1/accounts` and `GET /api/v1/accounts/{id}`.

**payments-service** (it decodes the response but never reads `currency`)
- `client/AccountsClient.java:15,18,21`: `get`, `debit` and `credit` return `AccountDto`. No code change, but it must be rebuilt.
- **Risk in `PaymentService.java:59-76`:** the return values of `debit` and `credit` are discarded, but the response body is still decoded. On the old contract that decoding fails with a client exception that is not a `RestClientResponseException`, so the `catch` blocks don't handle it. Result: the debit has already happened in accounts-service, the exception escapes, and no reversing credit runs. The payment is never saved and no `payments.completed` event is sent. That loses money silently, so payments-service must be upgraded before accounts-service, or the response shape must stay compatible. Alternatively, change these methods to return `void` or `ResponseEntity<Void>` so the body is never decoded.

**Not affected:** fraud-service and notifications-service. `currency` in `FraudCheckRequest`, `MoneyMovementRequest`, `PaymentRequest`, `PaymentDto` and `PaymentCompletedEvent` is a separate field and stays a String.

| gateway `GET /api/v1/accounts/{id}` | **nobody (likely public API)** |

No Kafka topic carries the change. The only topic, `payments.completed`, carries `PaymentCompletedEvent`, which has its own String `currency`.

## Consumers outside the workspace
- **Gateway `/api/v1/accounts` and `/api/v1/accounts/{id}`:** for external clients (frontends, mobile apps, partners), `"currency": "EUR"` becomes an object. That is a breaking API change. Version the endpoint, or map back to a String in the gateway.
- **The accounts-service `/accounts*` endpoints:** they may also be called directly by services this static graph can't see.
- **The bank-contracts artifact:** if it's published, other teams' code compiled against it breaks on `currency()`.

## Suggested rollout order
1. Release bank-contracts with a `Currency` type that accepts both a String and an object when decoding.
2. Rebuild and deploy payments-service and gateway-service on that version. If needed, keep the gateway's public response as a String.
3. Deploy accounts-service sending the object.

## Summary

`AccountDto` is the shared record in **bank-contracts** (`src/main/java/dev/demobank/contracts/AccountDto.java:5`): `record AccountDto(String id, String owner, String currency, BigDecimal balance)`.
